# llm_worker

## 미션별 llm_worker가 담당해야 하는 부분

아래는 박세환이 생각했을 때, 현재 5개 노드 구조에서 이 노드가 반드시 맡아야 하는 기능이다. 다른 노드와 담당이 겹치거나 판단이 필요한 부분은 여기에 적지 않았다. 그런 부분은 대회 중 회의·토론을 통해 정한다.

### 미션 1 — 전술명령 해석

- supervisor의 요청에 따라 대회 제공 LLM API로 전술명령을 해석한다.
- 지정표적·탐색 구역·거점을 추출하고, 정해진 형식·허용 코드값에 맞는지 검증해 결과를 반환한다.

### 미션 6 — 전장 위험도 분석

- 전달받은 구조화된 관측 정보를 텍스트로 대회 제공 LLM API에 입력해 상대 UGV의 위험도를 분석한다.
- 위험도 순위의 형식과 상대 식별값을 검증하고 결과를 supervisor에 반환한다.

### 미션 공통

- 대회 제공 텍스트 LLM API의 요청·응답 처리와 분석 실패 전달을 담당한다.
- 취소·마감이 지난 작업이나 이전 실행 세대의 결과를 폐기한다.

## 역할 및 구현 상태

M1 전술명령 해석과 M6 관측 정보 기반 위험도 분석을 담당한다.

초기 생성 시점(2026-11-15)에는 패키지 껍데기만 작성했다. 최신 구현 상태는 YAML의 해당 노드 항목과 실제 코드로 확인한다.

## 2026-11-18 구현 상태

실행 프로그램 `llm_worker_node`가 있다 (`ros2 run llm_worker llm_worker_node`). 팀장 결정으로 supervisor 쪽에서 만들었다.
**실제 경기의 명령문으로는 아직 돌려 보지 않았다** (명령문의 실제 문체를 모른다 — 낱말 표와 프롬프트는 API 문서의 예문과 추정으로 만들었다).

`/team/llm/analyze`의 `PARSE_ORDER`(M1)만 한다.

1. 낱말 규칙(`parser.py`)으로 명령문을 바로 푼다. LLM 없이도 답이 나온다
2. 대회 제공 LLM에 같은 명령문을 묻는다 (`llm.py`, 표준 라이브러리 HTTP). 답은 보고값으로 검증하고, 유효한 항목만 낱말 해석 위에 덮어쓴다 (`interpret.py`)
3. LLM 답이 `wait_s`(기본 4초) 안에 오면 합친 결과를 돌려준다. 안 오면 낱말 해석을 돌려주고 `error_code = "LLM_PENDING"` — LLM 요청은 뒤에서 계속 돌고, 같은 명령문으로 다시 물으면 그 답을 돌려준다. LLM이 실패했으면 `"LLM_FAILED"` — 다시 물으면 새로 요청한다
4. 어느 경우에도 `success = true`이고 `command`가 채워져 있다. 낱말 해석도 못 했을 때만 `false`(`NOTHING_PARSED`)

`ASSESS_THREAT`(M6)는 하지 않는다 (`UNSUPPORTED`). 순위는 supervisor가 목숨 · 탄으로 직접 낸다.
한 번에 한 요청만 받는다 (처리 중에 온 요청은 거절). 처리 중에는 0.5초마다 진행 알림(`requesting` → `validating`)을 낸다.

2026-11-18 확인: 대회 제공 키(Anthropic 형식)로 `claude-haiku-5-5` · `claude-sonnet-5-5` · `claude-opus-5-5`에 예문 두 개를 물었을 때 모두 1.2 ~ 2.0초에 답했고 낱말 해석과 같은 답이었다. 기본 모델은 `claude-opus-5-5`(effort `low`)로 두었다. **운영팀이 지정한 모델이 있는지는 확인하지 못했다.**

### 설정

로봇의 `~/team/secrets.json`의 `llm_api_key` (환경변수 `LLM_API_KEY`로도 준다). 저장소에 올리지 않고, 기록 · 출력 어디에도 찍지 않는다. 키가 없으면 낱말 해석만 한다.

`~/team/llm_worker.json` (없어도 된다)

- `provider`: `anthropic`(기본) · `openai`. `model`: 기본 `claude-opus-5-5`. `url`: 비우면 그 회사의 기본 주소 (운영팀이 다른 주소를 안내하면 여기에)
- `extra`: 요청 본문에 더 넣을 것. 기본 `{"output_config": {"effort": "low"}}` — 모델을 바꾸면 그 모델이 받는 것으로 맞춘다
- `timeout_s`(10): LLM 요청 하나의 시한. `wait_s`(4): 액션 한 번이 LLM 답을 기다리는 시간. `retry_after_s`(3): 실패한 뒤 다시 물어 오면 새로 요청하기까지의 간격

LLM에 물은 것과 받은 것은 `<기록 폴더>/llm_worker/llm.jsonl`에 남는다.

### 시험

```bash
cd 개발/src/llm_worker && PYTHONPATH=. python3 -m pytest -q test          # 낱말 해석 · LLM 답 검증 · 재시도 (ROS · 망 없이)
LLM_KEY_FILE=<키가 한 줄 든 파일> 임시_테스트_파일/supervisor_가짜상대/run_team_node.sh place 40 25 B-1    # 진짜 LLM 으로 한 경기
```

## 필수 작업 지침

- 작업 전 [공통 규칙](../../AGENTS.md), [통신 계약](../../../노드_관리/interfaces.yaml), [타입 정의](../team_interfaces/)를 읽는다. 노드 id는 `llm_worker`이다.
- 대회 제공 텍스트 LLM API만 사용한다. 영상은 perception의 구조화된 관측으로 전달받는다.
- LLM 출력은 정해진 필드·코드값으로 검증하고, 물리 제어·서버 보고는 직접 수행하지 않는다.
- 취소·마감·run_id가 지난 결과는 폐기한다. HTTP 요청 취소가 외부 연산 취소를 보장하지 않음을 구분한다.
- 인터페이스 변경은 사용자 승인 후 관련 정의·코드·YAML·changes를 함께 갱신한다. 이미 승인된 범위는 재확인하지 않는다.
- 다른 노드나 공통 타입 수정은 사전 승인을 받고, 연결된 노드의 영향을 확인한다.
- 현재 파일 존재만으로 구현 완료 처리하지 않는다. 구현 상태와 실제 소스 경로를 YAML에 맞춘다.
