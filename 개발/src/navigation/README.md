# navigation

## 미션별 navigation이 담당해야 하는 부분

아래는 박세환이 생각했을 때, 현재 5개 노드 구조에서 이 노드가 반드시 맡아야 하는 기능이다. 다른 노드와 담당이 겹치거나 판단이 필요한 부분은 여기에 적지 않았다. 그런 부분은 대회 중 회의·토론을 통해 정한다.

### 미션 2 — 지정표적 타격

- 지시받은 목표에 따라 차체를 이동·회전·정지시킨다.

### 미션 3 — 전장객체 인식

- 정찰을 위해 지시받은 위치로 이동하고 현재 위치를 추정한다.

### 미션 4 — 상대 UGV 타격

- 교전 과정에서 지시받은 차체 이동·회전·정지를 수행한다.
- 이동 중 장애물에 대응한다.

### 미션 5 — 목표거점 진입

- 전달받은 목표까지 경로를 계획하고 장애물을 회피하며 이동한다.
- 이동 진행·도착·실패를 전달한다. 좌표 도착과 주최측 센서의 점령 판정을 구분한다.

### 미션 공통

- 팀 코드의 `/cmd_vel` 발행을 단독으로 담당한다. 정지 명령도 이 노드가 발행한다.
- 제어 금지·취소·위치 데이터 단절·예외 시 차체를 정지시킨다.

## 역할 및 구현 상태

목표까지 이동하고 경로 계획·장애물 대응·정지를 담당한다.

초기 생성 시점(2026-11-15)에는 패키지 껍데기만 작성했다. 최신 구현 상태는 YAML의 해당 노드 항목과 실제 코드로 확인한다.

이 패키지에는 실행 노드가 두 개 있다 (2026-11-18 분리).

| 실행 파일 | 노드 | 담당 | 상태 |
|---|---|---|---|
| `navigation_slam` | `/navigation_slam` (`slam_node.py`) | 지도(`/team/navigation/map`, FieldMap)·자기 위치(`/team/navigation/pose`) 발행 | 구현 중 (SLAM 담당) — 출발 칸 초기화(잠긴 뒤 안 움직였으면 running 의 첫 지도에서 칸 전체를 라이다로 탐색, 항공 차량 검출 불필요), `/scan` 정합(상자·외벽 + ICP), `/odom` 이동량 + `/odom/odom_raw` 바퀴 방향(기본, `yaw_source:=imu` 로 `/imu/data`)으로 전파. 정합은 numpy(로봇 약 35 ms). `-p debug:=true` 면 `/team/navigation/debug` 에 내부 상태. 드론 지도 상자를 라이다로 고친다(아래 「지도 고치기」, `-p map_fusion:=false` 로 끔). 2026-11-18 UGV-08 모의 경기장에서 주행 노드와 함께 실차 확인(아래 「실차 시험」) |

## 주행 노드 (`navigation_drive`)

```bash
ros2 run navigation navigation_drive                       # 기본값
ros2 run navigation navigation_drive --ros-args -p max_v:=0.3 -p min_turn_w:=1.0
```

### 입출력

| 방향 | 토픽 · 액션 | 쓰는 곳 |
|---|---|---|
| 입력 | `/team/navigation/map` FieldMap (transient_local) | 벽·박스 → 5 cm 격자 (robot_radius 0.15 + 0.02 m 부풀림), `OTHER` 차량 → 임시 장애물 |
| 입력 | `/team/navigation/pose` PoseStamped, `arena` | 자기 위치 (SLAM). `header.stamp` = 그 위치가 맞는 시각 |
| 입력 | `/odom`, `/odom/odom_raw` (`/imu/data` 는 `yaw_source=imu` 일 때만) | SLAM 위치 사이를 메움. `/odom` 은 **이동 거리만** (orientation 상수, 11-18 실측), 방향 변화는 `odom_raw` 좌우 바퀴 누적 거리 `(Δ오른쪽−Δ왼쪽)/wheel_base_m`(0.175) — 로봇 odom 이 x·y 를 적분하는 내부 방향과 같은 식 (11-18 바퀴 기준으로 교체) |
| 입력 | `/scan` | 지도에 없는 점 → 임시 장애물(2.5 s, 라이다가 그 자리를 못 보면 마지막으로 본 뒤 20 s 까지) · 진행 띠(도는 호를 따라 굽힘) 1 m 안이면 감속, `0.30 m + 속도 × 0.45 s` 안이면 정지 |
| 입력 | `/team/perception/ugvs` PoseArray, `arena` (약 1 Hz) | 드론이 본 UGV 자리 (우리 차 포함). 막은 것이 서 있는 UGV 인지 · 헛돎 · 기억 칸 정리 — 정지 · 감속에는 쓰지 않는다 (아래 「드론이 본 UGV 자리 쓰기」) |
| 입력 | `/team/control/state`, `/team/mission/state` | 동작 허용(끊기면 정지 + `CONTROL_LOST`), run_id 확인 |
| 출력 | `/cmd_vel` | 목표 실행 중 16 Hz(`control_hz` — 브리지가 50 ms 안의 움직이는 명령을 버려서 20 Hz 에 딱 맞추지 않는다), 끝나면 0 을 5번 더. ±0.6 m/s, ±3.0 rad/s |
| 출력 | `/team/navigation/debug` | `debug_hz` > 0 일 때만 (기본 0). 경로 · 임시 장애물 · 단계 JSON — 시험 화면용 |
| 출력 | `/team/node_status` | 1 Hz + 위치 상태가 바뀔 때 |
| 액션 | `/team/navigation/navigate` | 아래 |

### Navigate 목표

- 좌표는 경기장 좌표(`arena`: x BLUE 벽→RED 벽, y 아래→위, m). sim-strategy 브랜치 `team/navigation/fieldmap.py` 와 같다.
- `mode`: `MODE_NORMAL` 경로 계획 → 따라가기 → 감속 정지 / `MODE_STRAIGHT` 회전 없이 시작 방향으로만 직진(M5 다가서기) / `MODE_ASSAULT` 0.6 m/s 유지, 제동 곡선으로 정지(M5 진입, 벽 가까운 목표 가능).
- 방향: `goal.pose.orientation` 으로 선다. `ignore_yaw=true` 또는 `yaw_tolerance_rad ≥ π`(supervisor 는 3.15) 이면 방향 무시.
- 실행 중 새 목표 → 이전 목표 `CANCELED`("새 목표로 교체됨"), 멈추지 않고 새 목표로.
- `REACHED` = 허용 오차 안에서 멈추고 0.3 s 뒤 다시 확인한 결과. M5 점령 판정과 별개.
- 막힘: 앞이 막히면 정지 → 0.7 s 기다림 → 임시 장애물을 넣고 다시 계획. 3 s 동안 가까워지지 못하면 피드백 `blocked=true` (계속 시도), 제한 시간에 막혀 있으면 `BLOCKED`.
  다만 지도에 없는 물체 때문에 나아갈 방법이 없는 채(그것을 지나야만 갈 수 있음 · 붙었는데 뒤도 막힘 · 돌 자리 없음) 5 s(`obstacle_give_up_s`) 지나면 **시한 전에 `BLOCKED`** (2026-11-19).
  지도에 없는 것이 차체 앞 0.12 m 안에 1 s 넘게 있으면 뒤로 뺀다 — 뒤에 벽 · 박스 · 지도에 없는 점이 있으면 빼지 않는다.
  서서 돌기(경로 · 도착 방향) 전에는 도는 쪽으로 쓸고 갈 자리에 지도에 없는 점이 6 cm 안으로 들어오는지 보고, 닿으면 반대쪽으로 길게 돌거나 물러난다.
  지도의 벽 · 상자 · 기둥에 차체가 겹치게 되는 회전도 하지 않고, 돌라는데 2.5 s 동안 모두 합쳐 11.5° 도 안 돌면 막힌 것으로 본다 → 자리에 와 있으면 바로 `REACHED` + detail `돌 자리 없음(도착 방향)`, 출발하려던 것이면 비켜 보고 안 되면 `BLOCKED` + `돌 자리 없음(출발)` (아래 「서서 돌기와 돌 자리」, 2026-11-19).
  도착 방향 맞추기는 10 s(`align_max_s`) 넘으면 남은 각도와 상관없이 `REACHED` — 시한까지 돌지 않는다.
- 자기 위치: 마지막 수신 0.3 s 넘음 → 0.15 m/s 제한, 0.6 s → 정지·대기(목표 유지), 대기 2 s → `LOCALIZATION_LOST`. 정상 복귀는 제때 온 위치 3번 연속.
- 우리 거점 진입 금지는 **하지 않는다** (supervisor 책임).

## 지도 고치기 (`navigation/map_fusion.py`, 2026-11-18 · 2026-11-19 실차 기록으로 고침)

드론 사진의 상자 찾기는 자주 틀린다. SLAM 노드는 드론 지도를 그대로 믿지 않고 라이다로 고친다.
계산은 ROS · slam 과 무관한 `map_fusion.py` 하나에 있다. slam_node 는 지도 받음(`set_map`) · 정합 기준(`structure`) · 정합 뒤 관측(`_observe_map`) · 내보냄(`_fused`) 네 곳에서만 부른다.

| 하는 일 | 방법 |
|---|---|
| 없는 상자 빼기 | 상자마다 점수(±4 안). 라이다 쪽 면에 점이 3개 넘게 맞으면 +1, 광선 2개 넘게가 상자(6 cm 줄인 것) 속을 10 cm 넘게 지나가면 −0.5, 둘 다면 +0.5. −3 이하 = 내보내는 지도 · 정합에서 뺌, +1 로 돌아오면 되살림. 가려진 상자는 그대로. 「맞은 점」 은 그 점까지의 광선이 이 상자 속을 지나지 않은 것만 센다 (속을 지나 뒤쪽 면 자리에 찍힌 점은 뒤에 붙은 다른 것이다) |
| 빠진 상자 더하기 | 벽 · 상자로 설명 안 되는 점에 맞는 40 cm 정사각형(라이다 쪽 면에 5점 넘게, 속을 지나는 광선 없음) → 후보. 1 s 넘게 3번 넘게 보이고 한 번이라도 30 cm 넘는 폭으로 보이면 **정합에 쓰는 상자로만** 더한다 (다른 UGV 차체 25 × 23 cm 는 안 된다). 후보 가까이에 어긋난 점이 보이면(움직이는 UGV) 버림. 더한 상자는 광선이 지나가면 −1 씩 깎아 다시 뺀다 |
| 안전장치 | 믿는 구조(외벽 + 라이다로 확인한 상자 — 고정 기둥은 가정한 자리라 넣지 않는다)에 맞은 점 10개 이상 · 지도로 설명되는 점 40 % 이상 · 0.6 rad/s 이하로 돌 때만 고친다. 정합에서 확인 못 한 드론 상자는 0.7 로 센다 — **후보 자세의 순위에만**, 통과 기준(맞은 점 수 ≥ max(12, 점의 25 %))은 무게 없이 센다(`slam_node.enough_hits`). 드론 지도에 상자가 없어도 외벽만으로 정합 |

## 결과 코드 · 비키는 동작 하나로 (2026-11-19, `drive/executor.py`)

**결과 코드** — Navigate 결과의 `detail` 끝에 `[코드]` 가 붙는다 (여럿이면 `[A] [B]`). 한글 문장은 사람이 읽는 것이고, 받는 쪽은 코드가 들어 있는지로 가른다. `outcome` 은 그대로다.

| 코드 | 함께 오는 outcome | 뜻 |
|---|---|---|
| `YAW_NOT_MET` | REACHED | 끝낸 방향이 요청한 허용 밖 (실제 방향은 `final_pose`). 어느 길로 끝났든 끝낸 자세로 계산해 붙인다 |
| `POS_NOT_MET` | REACHED | 끝낸 위치가 요청한 허용 밖 (돌진으로 벽 옆에 선 경우) |
| `NO_ROOM_AT_GOAL` | REACHED | 자리에서 도착 방향으로 서서 돌 수 없다 |
| `OBSTACLE` | BLOCKED | 지도에 없는 물체 때문에 나아갈 방법이 없다 — 나중에는 열릴 수 있다 (도착 방향만 막혀 REACHED 로 끝낼 때는 `NO_ROOM_AT_GOAL`) |
| `NO_PROGRESS` | BLOCKED | 가는 중 8 s 동안 가까워지지 못했다 |
| `NO_ROOM_TO_LEAVE` | BLOCKED | 목표 쪽으로 서서 돌 수 없다 |
| `BLOCKED_AT_TIMEOUT` · `INTERNAL_ERROR` | BLOCKED | 시한 때 막혀 있었다 · 주행 노드 내부 오류 |

**비키는 동작** — 지도에 없는 물체가 바짝 붙었을 때 어디로 비킬지는 돌 자리 만들기와 같은 계획(`_room_move_plan`)이 고른다.

- 지도 구조물과 지금 라이다의 지도에 없는 점을 함께 본다. 굴려 보는 동안 그 점에 더 붙는 후보는 버리고, 차체 가운데가 가장 멀어지는 것을 고른다.
- 라이다는 뒤쪽 90° 를 못 본다 — 뒤는 「빈 곳」 이 아니라 「모르는 곳」 이다. 같은 값이면 보이는 앞쪽으로 비키고(`blind_penalty`), 뒤로는 곧게 · 짧게만 뺀다.
- 목표에 가까워지지 못한 채 잇달아 `reverse_max`(3)번 뒤로 뺐으면 더 빼지 않는다. 0.30 m(`reverse_refill_m`) 가까워지면 다시 센다.
- 확인: `test_drive_core.ResultCodeTest` · `EscapeTest`. 가상 시나리오 31개 중 달라진 것은 「뒤에 UGV 가 붙은 채 앞 UGV 가 밀고 들어옴」 하나 (후진하며 민 주기 69 → 37). 실차로는 확인하지 않았다.
- 남은 것: 닿아서 바퀴가 헛도는 것을 바로 알아채는 감시는 아직 없다 — 뒤의 UGV 를 처음 몇 번 미는 것, 안 보이는 물체에 걸린 채 도는 것은 그대로다.
- supervisor 쪽 확인: [주행_결과_코드_확인_2026-11-19.md](../supervisor/docs/주행_결과_코드_확인_2026-11-19.md)

    규칙으로만 사라진다), 그 자리(0.15 m)에 다시 보이면 같은 UGV 로 이어 시간을 잇는다. 떠나는 것이 보인 궤적(움직이다 끊김)은 전처럼 지운다.

    라이다로 드론 UGV 를 반박하기 (오래 서 있던 궤적을 스캔 원본으로 본 18번이 모두 「그 자리에 무엇이 있다」 — 헛것이 이어진 증거가 없고, 위치가 틀린 구간에서는 잘못 반박해
    길이 번갈아 바뀔 수 있다), 아는 막힘이면 가지 않고 BLOCKED (공식 6판 147개 목표 중 1개에만 해당 · 위 실차 판에서는 뚫고 가서 자리에 닿았다),

| `log/<날짜_시각>/navigation_slam/debug.jsonl` | `start` · `map`(받은 드론 지도의 상자 수 · 차량) · `slot`(출발 칸 탐색 결과) · `state`(디버그 토픽과 같은 내용, `log_hz` 2 Hz) |

- 시각 `t` 는 노드 시계(초). `supervisor/events.jsonl` · `navigation.log` 와 같은 시계라 맞춰 볼 수 있다. 목표는 `no` 로 `goal` · `phase` · `result` 를 잇는다
- 크기: 가상 측정으로 주행 줄 평균 약 1 KB, SLAM 약 0.45 KB → 5분 30초 경기 한 판 수 MB. 한 파일 50 MB(`TEAM_LOG_LIGHT=1` 이면 10 MB)에서 `{"log": "truncated"}` 를 남기고 멈춘다. `TEAM_LOG_OFF=1` 이면 쓰지 않는다

- 끄기: `programs.json` 의 해당 줄 `args` 에 `--ros-args -p log_hz:=0.0`. 로봇에서 켜 본 것은 아직 아니다 (PC 의 가짜 ROS 시험 `test/test_run_log.py` 만)
- 보는 법 (예): `python3 -c "import json,sys; [print(r['t'], r['event'], r.get('phase') or r.get('outcome') or '', r.get('detail', '')) for r in map(json.loads, open(sys.argv[1])) if r['event'] in ('goal','phase','result')]" log/<날짜_시각>/navigation/debug.jsonl`

**로봇 기본 기동은 라이다를 켜지 않는다** (launch 주석 2026-10-16: 참가자 API 에서 빠져 기본 꺼짐). SLAM 은 `/scan` 이 없으면 위치를 못 낸다.

- **경기 · 포털 팀 테스트**: `team_node.py` 가 자식으로 켠다 (`개발/robot/lidar.sh`, `programs.json` 의 `lidar` 줄 — 8d6de0c). 손으로 켜 둔 라이다는 시작 대기에 들어가자마자 로봇이 끈다. 본 경기에서 팀이 켜도 되는지는 운영사무국 확인이 필요하다 [확인 필요]
- **웹 시험기**: `robot.sh start` 가 `/scan` 발행자가 없으면 아래를 대신 켠다 (`run.sh` 의 `launch lidar …`)

손으로 켤 때 (팀 테스트 · 경기 밖에서):

```bash
ssh team@<로봇 IP>                 # 비밀번호: 공식_자료/로봇_접속정보.md
sudo /usr/local/sbin/ugv-shell     # ROS 컨테이너 안으로 (인자를 받지 않는다)
source /opt/ros/humble/setup.bash && source /home/ws/ugv_ws/install/local_setup.bash
export ROS_LOCALHOST_ONLY=1        # 로봇 기본 노드들과 같게 (컨테이너 안에서만 통신)
setsid nohup ros2 launch ldlidar ld19.launch.py > /tmp/lidar.log 2>&1 &   # 창을 닫아도 계속 돈다
ros2 topic hz /scan                # 약 10 Hz 면 켜진 것
```

- 끌 때: `pkill -INT -f "ldlidar ld19.launch.py"` (웹 시험기로 켰으면 `robot.sh stop` 이 같이 끈다).
- 장치: LD19, USB `1a86:55d3` → `/dev/ttyACM0`, 230400 baud, `frame_id: base_lidar_link` (패키지 `/home/ws/ugv_ws/install/ldlidar`, launch `share/ldlidar/launch/ld19.launch.py`).
  `/dev/ttyACM0` 이 없으면 USB 선을 확인한다.
- `/scan`: 10 Hz, 한 바퀴 505점 중 launch 의 `angle_crop` 으로 뒤쪽이 가려져 유효 약 313점 ([시험기록/2026-11-18_cmd_vel_개방루프](시험기록/2026-11-18_cmd_vel_개방루프/README.md)).

## 필수 작업 지침

- 작업 전 [공통 규칙](../../AGENTS.md), [통신 계약](../../../노드_관리/interfaces.yaml), [타입 정의](../team_interfaces/)를 읽는다. 노드 id는 `navigation`이다.
- 팀 코드의 /cmd_vel 발행자는 이 노드 하나다. 정지도 이 노드가 속도 0으로 수행한다.
- 제어 허용 만료·위치 데이터 단절·취소·예외 시 정지하고, resume만으로 이전 목표를 자동 재개하지 않는다.
- 라이다·Depth·TF는 공식 규격을 확인한 뒤 계약에 추가한다. 토픽 이름이나 좌표 변환을 추측하지 않는다.
- 인터페이스 변경은 사용자 승인 후 관련 정의·코드·YAML·changes를 함께 갱신한다. 이미 승인된 범위는 재확인하지 않는다.
- 다른 노드나 공통 타입 수정은 사전 승인을 받고, 연결된 노드의 영향을 확인한다.
- 현재 파일 존재만으로 구현 완료 처리하지 않는다. 구현 상태와 실제 소스 경로를 YAML에 맞춘다.
