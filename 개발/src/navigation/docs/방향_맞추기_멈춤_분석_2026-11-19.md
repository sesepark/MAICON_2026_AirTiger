## 2. 원인 — 고치기 전 코드 (`8d83ef3` `navigation/drive/executor.py` `_align`)

```python
if abs(self._last.w) < 1e-6 or self._rot_since is None:
    self._rot_since = t                                    # 회전 시작 시각
margin = abs(self._last.w) * p.coast_s if t - self._rot_since >= p.latency_s else 0.0
if abs(err) <= self.goal.yaw_tol + margin:                 # 「멈춰도 조금 더 돈다」 → 일찍 멈춤
    self._state, self._settle_since = "settle", None       # → settle_s 0.3 s 뒤 다시 확인
    return STOP
w = _clamp(p.rotate_gain * err, p.rotate_max_w)            # 2.5 × err, 상한 1.6 rad/s
if abs(w) < p.min_turn_w:
    w = math.copysign(p.min_turn_w, err)                   # 하한 0.8 rad/s
```

일어나는 순서 (남은 각도 12°, 허용 5.7° 의 예):

1. 회전 명령 `w = 0.8`(2.5 × 0.21 = 0.52 → 하한 0.8)을 낸다
2. 0.3 s(`latency_s`) 가 지나면 여유 `0.8 × 0.2 = 0.16 rad`(9.2°)가 켜진다. 남은 12° ≤ 5.7 + 9.2 = 14.9° → **정지**
3. 실차는 그때 아직 돌지 않았다
   - 명령 반응 지연이 0.13 ~ 0.5 s 다 [실측, `시험기록/2026-11-18_cmd_vel_개방루프`]
   - 서서 돌 때는 정지 마찰 때문에 명령이 더 오래 이어져야 돌기 시작한다 [추정: 가상에서는 0.45 s 로 둠]
4. 0.3 s(`settle_s`) 기다린 뒤 다시 본다. 아직 12° 라 1 로 돌아간다 → 시한까지 되풀이한다
   - 한 바퀴가 회전 약 0.35 s + 정지 약 0.4 s 다
   - 실차의 「0.8 이 50번 · 0 이 60번 / 8 s」 와 비율이 같다

**멈춤 구간** — `허용 < |남은 각도| ≤ 허용 + coast_s × w(남은 각도)` 이고, `w(e) = min(1.6, max(0.8, 2.5·|e|))` 다.

| 허용 | 멈춤 구간 | 폭 |
|---|---|---|
| 0.10 rad (5.7°) — supervisor 기본 | 5.7° < 남은 ≤ **14.9°** | 9.2° |
| 0.20 rad (11.5°) | 11.5° < 남은 ≤ 22.9° | 11.5° |
| 0.35 rad (20.1°) | 20.1° < 남은 ≤ 38.4° | 18.3° |
| 0.50 rad (28.6°) — 2차 판 | 28.6° < 남은 ≤ **47.0°** | 18.3° |

- 허용을 넓히면 구간도 같이 올라간다. 남은 각도가 크면 `w` 가 커져 여유도 커지기 때문이다(최대 0.32 rad = 18.3°). 2차에서 0.5 rad 로 넓혀도 33 ~ 40° 에서 멈춘 까닭이다
- 크게 돌 때는 문제가 없었다. 차체가 실제로 돌기 시작한 뒤에 여유가 켜지면 맞는 동작이다. 문제는 「멈춤 구간 안에서 회전을 새로 시작할 때」 뿐이다
- 그런데 그런 경우가 흔하다. 정찰 자리에 와서 마지막에 맞추는 방향 차이가 대개 10 ~ 40° 이기 때문이다
- 이 시간 조건(`latency_s`)은 「막 돌기 시작한 짧은 회전에 여유를 주면 끝없이 되풀이한다」를 막으려고 넣은 것이었다 (코드 주석). 다만 0.3 s 가 실차가 돌기 시작하는 시간보다 짧았다
