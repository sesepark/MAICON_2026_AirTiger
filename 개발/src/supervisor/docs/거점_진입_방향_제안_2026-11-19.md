# 거점 진입(M5)에 도착 방향을 요구하지 않기 — navigation 쪽 제안 (2026-11-19)

navigation 담당이 supervisor 담당에게 드리는 제안입니다. **supervisor 코드는 고치지 않았습니다.** 받을지 말지, 어떻게 바꿀지는 supervisor 담당이 정합니다.
[주행 쪽 수정 제안 2026-11-19](주행_쪽_수정_제안_2026-11-19.md) 2절을 근거와 함께 자세히 쓴 문서입니다.

## 제안

`supervisor/mission.py` `_assault` 의 마지막 줄 (`80c43b1` 기준 507번째 줄):

```python
ports.go(gx, spots[i], heading, mode="assault")                 # 지금: yaw_free=False → 벽을 보는 방향(±yaw_tolerance_rad)까지 맞춘다
ports.go(gx, spots[i], heading, yaw_free=True, mode="assault")  # 제안: 자리만 맞추고 방향은 보지 않는다
```

`node.go` 는 `yaw_free=True` 면 `ignore_yaw=True` 에 `yaw_tolerance_rad=3.15` 로 보내므로(`supervisor/node.py:455-457`) 다른 곳은 바꾸지 않아도 됩니다. `heading` 은 넘겨도 쓰이지 않습니다.

## 왜 — 잃는 것이 없다

- **M5 판정은 거점의 광전센서가 「처음 가려지는 순간」입니다.** 차체 방향은 판정에 들어가지 않습니다.
  - `공식_자료/기존 정리/본선_기본정보.md:354` — 「거점 크기 1200×400, 광전센서로 판정, 처음 가려지는 순간 점령」
  - `공식_자료/텍스트/prestudy1_2026MAICON.md:460` — 출발·목표거점: 비접촉식 광전센서로 UGV 도착 여부를 자동 감지
  - 점령이 나오면 그 자리에서 경기가 끝납니다(`reporting`, UGV 정지·잠금). 들어간 뒤에 방향을 맞출 일이 없습니다.
- [확인 필요] 빔이 거점의 어디를 가로지르는지(입구 선인지, 안쪽인지)는 자료에 없습니다. 어느 쪽이든 방향과는 상관이 없습니다.

- 그때 자리를 다시 고르는 문제(50초에 60번)는 `4a5e3d0` 에서 고쳤습니다.

- 그래도 벽에서 0.175 m 인 목표에서 벽을 보도록 서서 돌면 차체 모서리가 벽에 닿습니다. 아래 가상 결과가 그렇습니다.

## 이것으로 안 풀리는 것 (navigation 쪽에서 볼 것)

- **가까운 쪽 자리(y 3.817)는 방향과 상관없이 3번 모두 시한까지였습니다.**
  - 그 자리는 1·2차에서 실제로 보낸 자리입니다.
  - 목표 5 cm 안까지 와 놓고, 벽에 앞이 붙은 채 지도에 없는 점을 기다리기와 서서 돌기를 되풀이합니다.
  - 이것은 navigation 의 문제이고 navigation 담당이 고칩니다. 그때까지는 supervisor 의 「거점 안이면 선다」가 꼭 필요합니다.
- 돌진 목표를 벽에서 더 떼는 것(x 0.175 → 0.25)도 견줘 보았습니다. 나아지지 않아 제안하지 않습니다 (REACHED 2/9).
  - 가까운 쪽 자리에서는 지도에 없는 벽 기둥 때문에 거점에 들어가기 전에 `BLOCKED` 가 2번 났습니다.
  - 이 기둥 문제는 navigation 의 [임시 장애물 부풀림 보고서](../../navigation/docs/임시_장애물_부풀림_2026-11-19.md)에서 다룹니다.
