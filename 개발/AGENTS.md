# 개발 공통 작업 규칙

- 작업 전 담당 패키지의 README.md, `../노드_관리/README.md`, `../노드_관리/interfaces.yaml` 및 관련 `.msg/.srv/.action`을 읽는다. 경로는 이 개발 폴더 기준이다.
- 초기 생성 시점(2026-11-15)에는 패키지·타입·통신 계약만 작성했다. 최신 구현 상태는 YAML과 실제 코드로 확인하며 실행 노드가 있다고 추정하지 않는다.
- 노드·토픽·서비스·액션의 추가·변경·삭제는 구현 전에 사용자 승인을 받는다. 이미 승인된 범위는 반복 확인하지 않는다.
- 다른 담당 노드 또는 공통 인터페이스 수정은 사용자 사전 승인을 받는다. 읽기·영향 분석은 허용한다.
- 통신 계약이 바뀌면 영향받는 정의 파일·코드·YAML을 같은 작업에서 갱신한다. 이름·타입뿐 아니라 필드 의미·단위·좌표계·QoS·주기·마감·취소·실패 처리도 변경에 포함된다.
- 자료형 구조의 원본은 team_interfaces의 `.msg/.srv/.action`이다. YAML에는 타입·정의 경로와 의미·연결·정책을 기록하며 자료형 구조 전체를 복사하지 않는다.
- YAML의 연결은 endpoints에만 기록한다. 구독자·호출자가 없어도 발행·제공 항목을 남긴다.
- 수정 직전 최신 YAML을 다시 읽고 관련 id의 항목만 고친다. 다른 담당자의 항목이나 전체 파일을 재생성해 덮어쓰지 않는다.
- 설계 확정·미구현 / 구현 중 / 구현 완료를 구분한다. runtime·알고리즘 없이 패키지 파일만 추가한 상태는 미구현이다. 미확인 값은 null로 둔다.
- 새 노드는 nodes와 endpoints에 추가한다. 같은 담당 영역은 기존 패키지, 독립 역할·의존성·실행 관리는 새 패키지를 고려한다. 타 노드 내부 모듈을 직접 import하지 않는다.
- ROS 계약·구현 변경은 changes에 대상·전후·사유·영향 노드를 기록한다. 웹 화면 수정은 ROS 이력에서 제외한다.
- 완료 전 정의 파일·실제 구현·YAML을 대조하고 HTML의 방향·상세·상태를 확인한다. 검증하지 못한 빌드·로봇 실행은 명시한다.
- 일회성 검사·mock·스크린샷은 `../임시_테스트_파일/`에 둔다. 루트 README.md와 공식_자료는 임의로 수정하지 않는다.
