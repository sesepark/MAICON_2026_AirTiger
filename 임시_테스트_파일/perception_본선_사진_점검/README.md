# 본선 경기장 드론 사진 점검 (check_pictures.py)

드론 사진 여러 장을 로봇의 지도 계산과 같은 순서로 돌려 보고, 사진마다 한 줄로 결과를 찍는다.
본선 경기장의 사진을 처음 받았을 때(2026-11-19 16:30 모의 경기) 무엇이 되고 무엇이 안 되는지 빨리 보려고 만들었다.
사진은 저장소에 넣지 않는다. numpy 와 OpenCV 만 있으면 돌고, ROS 는 필요 없다.

## 돌리는 법

```
/home/shnoh/military-ai-contest/.venv/bin/python check_pictures.py <사진 폴더 또는 jpg 파일들> --arena-height 5.0
```

- 어느 폴더에서 돌려도 된다 (perception 꾸러미는 이 파일 자리에서 `../../개발/src/perception` 으로 찾는다).
- `--arena-height`: 지도에 적을 경기장 세로 (m). 본선 경기장은 5.0 (기본값), 연습 경기장 사진은 4.8 을 준다. 가로는 6.12 로 고정이다.
- `--out 폴더`: 그림과 `결과.json` 을 둘 곳. 주지 않으면 첫 사진이 있는 폴더 아래에 `점검_결과` 폴더를 만든다.
- `--cache 파일`: 경계 저장 파일. 주지 않으면 사진마다 경계를 처음부터 찾는다 (새 카메라의 첫 계산과 같다).
  주면 로봇처럼 통과한 경계를 그 파일에 남기고 다음 사진은 거기서 출발한다 (로봇의 두 번째 계산부터와 같다). 시험용 새 파일 이름을 준다.
- 사진 한 장에서 오류가 나도 그 줄에 오류를 찍고 다음 사진으로 넘어간다.

## 나오는 것

1. 사진마다 한 줄 (아래 「칸의 뜻」).
2. 맨 끝에 요약 표 (사진마다 한 행).
3. `--out` 폴더에 사진마다 그림 한 장 (`01_이름_점검.jpg`) 과 `결과.json` (찍은 값 전부와 경계 · 상자의 설명 글).

그림은 왼쪽이 원래 사진, 오른쪽이 위에서 본 그림(1 m = 100 px)이다.
- 주황 선: 맞춘 구역선 (세로선 다섯 · 줄 경계선 둘 · 가운데 원). 사진의 흰 선과 겹쳐야 맞게 맞춘 것이다.
- 굵은 초록 선: 경기장 바닥의 네 변 (경계 검사를 통과하지 못했으면 빨강). 분홍 점: 경계가 쓴 흰 선 점.
- 초록 네모: 상자 바닥, 노란 네모: 상자 윗면, 숫자: 상자 번호, 빨간 X: 버린 후보, 하늘색 +: 카메라 바로 아래 점.
- 오른쪽 그림의 보라색: 사진에 찍히지 않은 자리.

## 칸의 뜻

| 칸 | 뜻 |
|---|---|
| 파일 | 사진 이름 (같은 이름이 여럿이면 폴더까지) |
| 크기 | 사진의 가로x세로 px. 연습 카메라는 1280x720 |
| 경계 OK / 실패 / 없음 (방법) | 경계 검사를 통과했는가. 실패면 대괄호 안에 통과하지 못한 검사(경계 설명 중 「실패」 로 시작하는 것)를 적는다. 방법: search = 처음부터 찾음, prior = 지난 경계에서 출발, prior_refit = 지난 경계 둘레로 다시 맞춤 |
| 선 | 경계가 찾은 선 묶음마다 점 수. Bs · Rs = 두 끝 띠 선, Bc · Rc = 두 CM 선, C = 중앙선, top · bot = 줄 경계선 둘, circle = 가운데 원. 0 이면 그 선을 못 찾은 것 |
| 끝띠 · CM · 원 · rms | 벽에서 끝 띠 선까지 (m) · 중앙선에서 CM 선까지 (m) · 원 반지름 (m) · 맞춘 뒤 선 점들의 오차 (cm) |
| 보임 x · y | 사진에 찍힌 경기장 범위 (m). x 는 경기장 세로 가운데 높이의 가로줄에서, y 는 경기장 가로 가운데의 세로줄에서 잰 것. 좌표는 경계를 맞춘 좌표 (x: BLUE 벽 0 → RED 벽 6.12, y: 아래 벽 0 → 위 벽 5.00). 0 보다 크게 시작하거나 벽 값보다 작게 끝나면 그만큼 잘린 것. 「밖」 = 벽 밖 1.5 m 넘게 찍힘 |
| 벽 B R 아래 위 % | 네 벽의 바닥선 중 사진 안에 있는 비율. B = BLUE 벽, R = RED 벽 |
| 끝띠선 B R % | 두 끝 띠 선 중 사진 안에 있는 비율 |
| 상자 n (붙은 a, 잘린 b) | 찾은 상자 수. 붙은 = 붙어 있는 상자 줄을 나눠서 얻은 상자, 잘린 = 윗면 한 변이 사진 밖이라 다른 상자의 크기로 채운 상자. 「검사 실패」 가 붙으면 상자 검사를 통과하지 못한 것 |
| s (카메라 높이, 방법, 옆면 수) | s = 카메라 높이 / (카메라 높이 − 0.4). measured = 상자 옆면으로 잼, default = 재지 못해 기본값 |
| 나눗값 x/y (출처) | 윗면 가운데를 상자 가운데로 옮길 때 쓴 값. grid = 바닥 격자에 맞춤, s = 잰 s 그대로 |
| 버림 | 버린 상자 후보를 까닭별로 센 것 |
| 경기장 | 지도에 적은 가로x세로 (m) |
| 거점 BLUE · RED | 벽 그림으로 읽은 1 · 2 · 3번 줄의 거점 (지휘 = 작전지휘소, 정비 = 정비소, 보급 = 군수보급소) 와 둘째 배치와의 차이. 0.20 보다 작으면 모름. 모름이면 괄호 안에 까닭 |
| 지도 나감 / 안 나감 | 로봇이 이 사진으로 지도를 내보내는가 (경계 검사 통과 + 상자 검사 통과 + 상자 1개 이상) |
| 초 | 경계 · 상자 · 벽 그림 · 합계에 걸린 시간 (이 PC 기준. 로봇은 4 ~ 5배 느리다) |
| 주의 | 눈으로 확인할 것. 연습 경기장 값의 범위를 벗어난 값, 사진 밖에 있는 벽, 못 찾은 선, 모름인 거점 등. 틀렸다는 뜻이 아니라 그림을 보라는 뜻이다 |

「주의」 에 쓰는 범위 (연습 값보다 조금 넉넉하다): 끝띠 0.78 ~ 0.90, CM 0.59 ~ 0.64, 원 0.60 ~ 0.65, rms 1.5 cm 이하, s 1.13 ~ 1.21, 사진 크기 1280x720.

## 본선 경기장 사진을 받으면 먼저 볼 것

1. **사진 크기**가 그대로 1280x720 인가. 다르면 렌즈 가운데와 축척이 달라지므로 경계 쪽에 먼저 알린다.
2. **좌우가 잘렸는가**: 「보임 x」 가 0 보다 크게 시작하거나 6.12 보다 작게 끝나면 그쪽 벽이 사진 밖이다. 「끝띠선 B R %」 가 낮으면 끝 띠 선도 사진 밖이다 (연습 사진은 90 % 남짓).
3. **선을 다 찾았는가**: 「선」 의 여덟 묶음(세로선 다섯 Bs Bc C Rc Rs · 줄 경계선 둘 top bot · 원 circle)에 0 이 없는가. 그림에서 주황 선이 사진의 흰 선과 겹치는가.
4. **끝띠 · CM · 원 · rms 가 연습 값과 비슷한가**: 연습 값은 끝띠 0.81 ~ 0.88, CM 0.60 ~ 0.62, 원 0.61 ~ 0.63, rms 1 cm 아래.
   경계가 OK 여도 이 값이 다르면 선을 잘못 고른 것일 수 있다. 예: 연습 사진 한 장(위아래가 많이 잘린 것)은 경계 OK 인데 원 0.70 · 끝띠 0.90 이었고, 그림을 보면 원과 줄 경계선이 사진과 어긋나 있었다.
   저장소의 연습 사진(drone_test1.jpg)의 좌우를 300 px 씩 잘라 낸 것도 경계 OK · 지도 나감인데 원이 0.69 였고, 그림에서 아래쪽 줄 경계선과 상자 네모가 어긋나 있었다.
   → 원 반지름이 0.66 을 넘으면 경계가 OK 여도 그림부터 본다.
5. **카메라 높이**: s 가 연습 값(1.15 ~ 1.19, 카메라 높이 2.5 ~ 3.1 m)과 비슷한가. 방법이 default 면 옆면을 재지 못한 것이다.
6. **상자 수**: 그림에서 눈으로 센 상자 수와 「상자 n」 이 같은가. 초록 네모가 상자 바닥 자리에 놓였는가. 사진 끝에 걸린 상자(잘린 b)가 있는가. 빨간 X 가 진짜 상자 위에 있지 않은가.
7. **거점 벽 그림**을 읽었는가, 모름인가. 벽이 사진 밖이면 모름이 맞다 (그때 supervisor 는 거점을 차례로 들어가 본다). 읽었으면 그림에서 벽 그림과 맞는지 한 번 본다.
8. **걸린 시간**: 합계에 4 ~ 5를 곱한 값이 로봇에서 걸릴 시간이다. 로봇은 경기 시작 뒤 30초 안에 지도를 못 만들면 벽만 있는 임시 지도를 낸다.
9. **지도 나감**인가. 안 나감이면 그 줄의 경계 실패 까닭과 「주의」 를 본다.

## 경계 맞추기에서 2026-11-19 오후에 바뀐 것 (이 표를 읽을 때 알아 둘 것)

- **검사가 엄해졌다.** 경계 OK 는 이제 치수까지 맞는다는 뜻이다: 끝띠 0.75 ~ 0.96 · CM 0.56 ~ 0.67 · 원 0.57 ~ 0.68 · 원 / CM 0.97 ~ 1.08 ·
  (가운데 ~ 끝 띠 선) / CM 3.40 ~ 3.85 · 선 위 흰 선 비율 0.75 이상. 위 4번에 적은 「경계 OK 인데 원 0.70」 같은 경우는 이제 실패로 나온다.
  실패 까닭은 그 줄의 대괄호에 찍힌다 (예: `실패 원 반지름 / CM 반폭 1.15` = 가로 줄 경계를 잘못 골랐다, `실패 CM 반폭 1.05 m` = 바닥 깔개의 이음매를 CM 선으로 골랐다).
- **방법 칸**: `search` 처음부터 찾음 · `prior` 지난 경계(저장 파일이나 코드에 실린 것)로 선을 골라 맞춤 · `prior_refit` 지난 경계 둘레의 점으로 다시 맞춤.
  뒤에 `·줄임` 이 붙으면 줄어든 맞추기다: 세로선 다섯 개를 다 찾지 못해(좌우가 잘림 · 끝 띠 선이 가려짐) CM 선 둘 · 중앙선 · 가로 줄 경계 · 원으로 맞춘 것.
  `·끝띠어림` 이 붙으면 끝 띠 선이 하나도 안 보여 끝 띠를 CM 반폭 × 3.635 로 어림한 것이다 (0.80 ~ 0.90 m 로 자름) — 구역의 바깥쪽 경계가 몇 cm 틀릴 수 있다.
- **줄어든 맞추기가 버티는 범위** (연습 사진 19장을 자르고 · 키우고 · 밀어 만든 646장, PC): 좌우를 25 % 씩 잘라도 다섯 선이 다 보여 그대로 된다.
  30 ~ 36 % 를 자르면 세 선으로 맞추고 (19장 중 16 · 13 · 10장 통과, 원본과의 차이 최대 5 ~ 7 cm), 40 % 부터는 실패한다. 네 변을 30 % 씩 잘라도 17장 통과.
  화면이 옆으로 밀린 것(렌즈 가운데가 화면 가운데에서 먼 것)은 20 % 까지 맞고(원본과 2 cm 안), 30 % 는 실패한다 — 틀리게 맞추느니 실패하게 해 뒀다.
- **실패하면** 로봇은 30초 뒤 벽만 있는 임시 지도를 낸다. 그 사진을 `make_boundary_entry.py` 에 넣어 겹친 그림으로 어느 선이 문제인지 본다.

## 본 경기 카메라의 경계를 코드에 넣기 (make_boundary_entry.py)

카메라는 틀에 고정돼 있어 한 번 맞춘 경계를 계속 쓸 수 있다. 모의 경기에서 받은 본 경기 카메라 사진 중 선이 잘 보이는 것 한 장으로:

```
/home/shnoh/military-ai-contest/.venv/bin/python make_boundary_entry.py 사진.jpg --camera main
```

- 경계를 처음부터 맞추고, 사진 옆에 `<이름>_경계.jpg` (왼쪽 원본 + 선, 오른쪽 위에서 본 지도) 를 쓴다. 주황 선이 흰 선 위에, 원이 원 위에 놓였는지 눈으로 본다.
- 검사를 통과하면 `"main": {...},` 한 줄을 찍는다 → `개발/src/perception/perception/camera_boundaries.py` 의 `BUILT_IN` 에서 `"main": None,` 줄을 그것으로 바꾼다.
- 통과하지 못하면 값을 찍지 않는다. 다른 사진으로 다시 한다.
- 넣은 뒤 확인: `check_pictures.py <폴더> --camera main` 의 방법 칸이 `prior` 로 나오고 경계 시간이 0.2초 안쪽이면 된다.
