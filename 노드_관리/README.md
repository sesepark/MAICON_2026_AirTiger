# ROS 2 구성 관리

AI가 개발 전 읽고 변경 후 갱신하는 공통 통신 계약이다. HTML은 YAML과 저장소의 실제 타입 정의를 보여준다. 초기 생성 시점(2026-11-15)에는 패키지·타입 껍데기만 작성했다. 최신 구현 상태는 YAML의 노드별 상태와 실제 코드로 확인한다.

## 작업 지침

- 작업 전 `interfaces.yaml`, 담당 패키지 README, 관련 `.msg/.srv/.action`을 읽는다.
- 노드·토픽·서비스·액션 변경은 사용자 승인 후 관련 정의·구현·YAML을 함께 갱신한다. 이미 승인한 범위는 재확인하지 않는다.
- 구조 원본은 `개발/src/team_interfaces/`. YAML에는 타입·정의 경로·필드 의미·단위·좌표·성공/실패·취소 정책을 기록한다. 자료형 구조를 복사하지 않는다.
- `packages`는 패키지, `nodes`는 실제 ROS 이름·담당자·구현 상태를 관리한다. 실행 코드가 생기면 `source_files`와 상태를 갱신한다. 계약 변경 시 `updated`·`checked_at`도 갱신한다.
- 로봇이 기본으로 실행하는 대회 측 노드는 상태 `대회 제공`, 패키지 `kind: "official"`·`path: null`·`robot_path`(로봇 안 경로)로 기록하고 그래프에 점선 카드로 표시한다. 팀이 고칠 수 없으므로 로봇 실측(`ros2 node info`·`ros2 topic info -v`)으로만 갱신한다.
- 연결 관계는 `topic_endpoints`, `service_endpoints`, `action_endpoints`에만 기록한다. 구독자·호출자가 없어도 발행·제공을 기록한다.
- 발행/구독 QoS·주기·수신 제한·원본 데이터 나이·실패 동작을 구분한다. 서비스는 완료 의미·타임아웃·재시도, 액션은 목표 교체·취소·마감·피드백 제한도 기록한다.
- 수정 직전 최신 파일을 읽고 관련 id만 수정한다. `changes`에는 ROS 계약·구현 변경의 전후·사유·영향 항목을 기록한다. 웹 수정은 제외한다.
- 확인하지 않은 외부 설정은 null. 설계값과 실제 코드·실측값을 구분한다. YAML을 수정해도 ROS 설정에 자동 적용되지 않는다.
- 완료 전 정의 파일·구현·YAML을 대조하고 화면에서 방향·노드별 입출력·정의 원문을 확인한다.

## 화면 열기

저장소 루트에서 `python3 -m http.server 8767 --bind 127.0.0.1` 실행 후 `http://127.0.0.1:8767/노드_관리/architecture.html`을 연다. 이미 같은 서버가 있으면 재사용한다. ROS나 경기 서버를 실행하는 명령이 아니다.

첫 화면은 **토픽 전체**다. 카드·라벨을 작게 표시하며 휠/트랙패드로 포인터 위치를 확대하고 빈 곳을 드래그해 이동한다. `전체 맞춤`으로 돌아온다. `연결 요약`은 같은 두 노드의 통신을 방향별로 묶으며 선이나 개수를 누르면 전체 목록을 보여준다. 두 보기 모두 노드를 누르면 외부 장비 연결과 미연결 발행·제공 항목까지 확인한다.

HTML은 같은 폴더의 YAML과 저장소 안 타입 파일을 직접 읽는다. HTML 더블클릭 시에는 YAML과 정의 파일을 수동 선택할 수 있으며 미선택 원문은 미확인으로 표시한다. 내장 데이터 복사본은 없다. YAML 갱신 후 새로고침으로 다시 읽는다.
